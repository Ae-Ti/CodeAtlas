핵심 기능이라 가장 길게. **말로 설명하지 말고 클릭 동선이 스스로 말하게 한다.**

| 1-4 | 1위 코드 클릭 | Monaco 뷰어가 해당 파일을 열고 **매칭 줄(30행 부근) 하이라이트** |

> 대사 예시: "multi-head attention 단락을 클릭하면, 이 논문의 공식 구현 저장소
> 안에서 대응 코드 5개를 보여줍니다. 1위는 사람이 검수한 매핑이고, AI 설명은
> 미리 계산돼 있어 바로 뜹니다. 코드를 클릭하면 해당 줄이 하이라이트되고,
> GitHub 원본으로 검증까지 갈 수 있습니다."

**여기서 검색 품질 수치를 언급** (결과보고서와 같은 표현으로 — "개선"이 아니라 "교정"):
"논문 범위 안에서 Top-5 65.4%, 사람이 후보 5개 중 고르는 전제입니다."

## 시나리오 2 — MCP Agent 자연어 질의 (Segment Anything, 55초)

| 단계 | 클릭 | 화면에 나와야 할 것 |
|---|---|---|
| 2-1 | 상단 메뉴 → **Agent** (`/agent`) | 질의 입력창 + 예시 질문 버튼 |
| 2-2 | 입력: **"SAM의 mask decoder는 코드로 어떻게 구현됐어?"** | MCP tool 카드가 순서대로 done 처리되는 타임라인 (SearchPaperChunk → FindCodeImplementation → …) |
| 2-3 | 결과 카드 | 매칭된 SAM 단락(**"Mask decoder."** — 8.24 실측 1위, 0.718) + 코드 후보 + TACC 요약("후보 N개 중 제외 M개 → 5개 선택") |
| 2-4 | `precomputed` 배지 짚기 | "무거운 생성은 큐레이션 때 한 번, 조회는 즉시" |
| 2-5 | 입력: **"How is multi-head attention implemented in PyTorch — what tensor shape changes happen?"** → 결과 아래 **"이 질문에 대한 AI 답변 생성"** 클릭 | `LIVE 생성` 배지 + 텐서 shape 변환 답변("(batch, seq, n_head, d_k)로 재구성 … transpose …"). 위의 사전계산 근거는 그대로 남아 있음 |
| 2-6 | 입력: **"In multi-head attention with h=8 heads, what dropout rate was applied during training?"** → 같은 버튼 | **"이 섹션에는 드롭아웃률에 대한 정보가 나와 있지 않다"** — 자료에 없는 건 없다고 답한다 |

> 대사 예시: "화면을 벗어나서, 자연어로 바로 물을 수도 있습니다. MCP tool 4종이
> 검색→코드매칭→컨텍스트 선별을 순서대로 수행하고, TACC가 후보를 걸러낸 근거를
> 그대로 보여줍니다."
>
> 2-5/2-6 대사: "위의 근거는 미리 계산해 둔 매핑 설명이고, 질문 자체에 답이 필요하면
> 그 자리에서 생성합니다. 같은 화면에서 0.05초와 20초가 나란히 보이는 게 왜 미리
> 계산해 두는지의 답입니다 — 그리고 자료에 없는 건 없다고 말합니다."

**2-5/2-6은 반드시 둘 다, 이 순서로.** 좋은 답 하나만 보여주는 것보다 "있으면 답하고
없으면 없다고 한다"까지 보여주는 쪽이 강하다 — 지어내지 않는다는 걸 말이 아니라
화면으로 증명하는 장면이다 (#51 리뷰 A 제안). 두 질의 모두 §3.2.2 Multi-Head
Attention 단락을 1위로 잡는 것을 리허설에서 확인했다(0.704 / 0.751). 한국어 질의는
같은 뜻이라도 다른 단락("4 Why Self-Attention")을 잡으므로 **영문 문구 그대로** 입력.
생성 대기(실측 18~31초)는 편집에서 컷하고 "Qwen3 생성 NN초" 자막으로 대신한다 —
2-5/2-6은 정직한 실측 시간을 그대로 보여주는 장면이기도 하다. 2-6이 60초 타임아웃으로
실패 카드가 뜨면 "다시 시도" 한 번, 또 실패하면 2-5까지로 마무리한다.
2-5 답변도 끝에 "…는 나와 있지 않다"가 붙을 수 있다(실측). 2-6의 대비가 약해지면
대사로 짚는다 — "방금 것도 아는 만큼만 답하고 나머지는 없다고 했습니다." 

**질의 문구는 8.24 사전 검증으로 고정됨** — 리허설 없이 촬영으로 직행하는 일정이라
세 질의 모두 seed_dump 기준선에서 1위 매칭을 실측했다: 2-2 SAM "Mask decoder."
0.718(top 3 이 전부 SAM) · 2-5 §3.2.2 0.704 · 2-6 §3.2.2 0.751. **당일 변형 금지 — 글자 그대로 입력**
(질의→chunk 매칭은 전체 코퍼스 벡터 검색이라 문구에 민감하다).

## 시나리오 3 — NL2SQL + 연결 그래프 (40초)

| 단계 | 클릭 | 화면에 나와야 할 것 |
|---|---|---|
| 3-1 | Agent 페이지 하단 **NL2SQL** 섹션 | 예시 버튼 3개 |
| 3-2 | 예시 버튼 **"2020년 이후 발표된 논문의 제목과 발표일"** 클릭 | **생성된 SQL 원문** + `title`·`published_date` 두 컬럼 표. "SQL을 숨기지 않고 보여준다 — 검증 가능성" |
| 3-3 | 상단 메뉴 → **Graph** (`/graph`) → 논문 칩 **"Segment Anything"** 클릭 | 전체 뷰(논문 9편 클러스터 지도) → 그 논문 클러스터만 화면 맞춤 + **유사도 라벨 표시** (#58 칩) |

> 대사 예시: "메타데이터는 자연어로 SQL을 생성해 조회하고 — 생성된 SQL을 그대로
> 노출해 검증할 수 있습니다 — 카탈로그 전체의 논문-코드 연결은 그래프로 조망합니다."

**NL2SQL은 예시 버튼만 누른다. 행 수·SQL 문장을 대본에 적지 않는다.** 생성 SQL이
회차마다 달라진다 — 같은 예시가 `> '2020-01-01'`(5행)로도 `> '2020-12-31'`(4행, ViT
누락)로도 나온 실측이 있다. 빈 표는 고장으로 보이지만 **틀린 숫자는 맞는 답처럼
보인다**. "star 수 상위 3개" 예시는 `SELECT *`가 생성돼 commit_hash까지 쏟아지므로
3-2에서는 컬럼을 지목한 예시를 쓴다. 자유 입력은 금지 — "논문별 chunk 수"가
`paper_repositories`를 세서 전부 1을 자신 있게 반환한 실측이 있다(A, #51 리뷰).

## 시연 전 점검 (당일 아침, 순서대로)

**0. DB 를 seed_dump 기준선으로 복원하고, 이후 촬영이 끝날 때까지 업로드·적재 금지.**
검색 품질 수치(315쌍·Top-5 65.4%)와 결과보고서·README 서술이 전부 **논문 9편 기준**이다 —
10편 상태로 찍으면 화면·대사·보고서가 서로 어긋난다. 업로드 시연(시나리오 4)을 찍을 거면
**마지막 테이크**로 빼고, 찍은 뒤 다시 복원한다.

```bash
./scripts/reset_db.sh && docker exec -i codeatlas-postgres psql -U codeatlas -d codeatlas < database/seed_dump.sql
# → 백엔드를 CODEATLAS_EMBEDDING_BACKFILL=true 로 한 번 재기동 (임베딩 ~1분)
```

```bash
./scripts/doctor.sh                          # 1. Ollama·DB·백엔드 환경
docker exec -i codeatlas-postgres psql -U codeatlas -d codeatlas \
    -tAc "SELECT count(*) FROM papers"       # 2. = 9 인지 (seed_dump 최종본)
curl -s -X POST localhost:8080/api/admin/curate-pending   # 3. pending 0건 확인
./scripts/smoke.sh                           # 4. 8/8 통과
# 5. 「사전 검증 기록」 목록을 그대로 한 번 밟는다 — 촬영이 첫 실행이 되지 않게.
#    하나라도 어긋나면 촬영을 멈추고 원인부터 본다.
```

3번이 핵심이다 — **pending이 남아 있으면 그 chunk는 시연 중 라이브 폴백으로
16~27초를 기다린다.** `chunksPending: 0` 응답을 확인해야 시연 전 준비가 끝난 것.
(업로드 작업이 도는 중이면 이 curl 과 업로드의 큐레이션 단계가 배치 가드에 걸린다 —
업로드 쪽은 기다렸다 이어가지만, 애초에 점검 시점엔 업로드 작업이 없어야 한다: 0번 규칙)

| 리스크 | 증상 | 대응 |
|---|---|---|
