## 2. §5.1 원인 규명 왕복 — "3건의 거짓 억제"가 세 층으로 갈라지기까지

이 왕복이 이번 기간의 중심입니다. 각 단계가 상대의 반증으로 교정됐습니다.

| 라운드 | 주장 | 반증·확정 |
|---|---|---|
| ① B: "FN 17·18·55 는 한계" | — | A 가 17·18 을 **전처리 결함으로 규명** — `latex_to_text` 가 수식을 자리표시자로 뭉개 `W^Q`·`h=8` 같은 매핑 근거를 지움. A/B 재현 포함 |
| ② B: 수정 반영, "남은 FN 29·31 은 실행 간 경계 변동" | A 가 **재현 실패로 반증** — temp 0 반복 3회(+seed 고정 3회)가 **4개 섹션 전부** 동일. 한 섹션이었다면 약했을 반증이 네 섹션 일치로 성립. (4회째 반복은 #47 리뷰 때 추가 확인 — 반증 시점 근거는 3회) |
| ③ B: v4 산출물 추적으로 재분해 | **둘 다 절반씩** — chunk 수·판정 표본 변동은 타임아웃→폴백(A 가설 확인), FN 29·31 은 **환경 간 판정 불일치**(같은 프롬프트·temp 0, A 환경 true / B 환경 false) |
| ④ A: 비대칭 확인 | 갈린 조각(sin/cos 수식)에서 **A 환경은 정답 심볼까지 적중, 오답은 B 환경** — 불일치가 대칭이 아님을 §5.1 에 명시 |

### 확정된 §5.1 의 골자

- 거짓 억제 3건 = **전처리 결함 2건(원인 규명·수정 완료) + 진짜 한계 1건(References)**,
  그리고 환경 간 불일치라는 별도 축
- 남은 과제는 "판정 품질"이 아니라 **호출 안정성(타임아웃·재시도) + 환경 간 재현성**
- **제품 경로는 영향 없음** — 순위는 pgvector, LLM 설명은 seed_dump 에 결과물로
  커밋 → "LLM 이 비결정적이면 재현성은?"에 설계로 답이 돼 있음 (제10조① 근거)
- 호출 안정성은 코드로도 반영(#48): seed 고정, timeout 480, 재시도 3회 + backoff

- **#45**: 61건 어림수 제거 — **A(저장소 미배포) 24건·39.3% / B(코드 대상 아님) 32건
  / C·D(우리 몫) 5건·8.2%**. ResNet 저장소가 prototxt 한 파일뿐이라 A 유형 15건이
  거기서 나옴. "매핑률 83.8% 왜냐" → "39.3%는 저작자 미공개, 우리 몫은 8.2%"로 방어.
- **논문별 Top-1/Top-5 표** 신설 — Llama 3 100% ↔ ResNet 45.2%. "저장소 코드의
  성격이 검색 품질을 좌우"가 논문 단위로 보이며, §5.1(A 39.3%)과 같은 결론을 가리킴.
  B 해석 문단의 축이 된다.

## 6. 기록해둘 판단 근거

- **원인에 이름을 붙이기 전에 재현하거나 추적한다.** "실행 간 변동"은 그럴듯했지만
  A 의 반복 실험 한 번에 무너졌고, 진짜 원인(폴백 / 환경 간 불일치)은 산출물 추적이
  갈라냈다. 이름이 틀리면 다음 반복 방향도 틀린다.
- **불일치는 대칭인지까지 확인한다.** 두 환경이 갈렸을 때 어느 쪽이 맞았는지를
  기록해야(오답 = B 환경) 서술이 완결된다.
- **비결정성 방어는 "결과물 커밋" 구조가 한다.** 제품 경로가 영향받지 않는 이유를
  한 문단으로 적어두면 제10조① 대응이 우연이 아님이 드러난다.
- **어림수는 제출 문서에서 뺀다.** ~54/~7 은 정밀 집계에서 24/32 로 교정됐다 —
  틀린 정도가 아니라 결론(저장소 미배포가 40%)을 바꾸는 수준이었다.
- **검증 절은 "무엇을 잡았나"로 쓴다.** 형식적 검증 목록보다 실제로 잡힌 결함
  목록이 체계의 실증이다 (#44 §2.5).
