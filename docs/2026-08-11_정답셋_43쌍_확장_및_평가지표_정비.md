## 2. 정답셋 43쌍 — 절대 수치는 떨어지고 상대 성능은 유지

### 2.1 무엇이 바뀌었나

| | 9쌍 | 43쌍 |
|---|---|---|
| 매핑된 chunk | 9 | **43** |
| 매핑 건수 | 14 | **52** |
| codeBlocks | 13 | **33** |
| 부모–자식 겹침 | 3쌍 | **0** |
| 인덱싱 대상 파일 | 5 | 8 (`Layers.py`, `train.py`, `translate.py` 추가) |

### 2.2 수치 — 배수로 봐야 합니다

| | 9쌍 | 43쌍 | 랜덤 하한 | 배수 |
|---|---|---|---|---|
| ② single + demo제외 | 77.8% | 25.6% | 7.7% → 3.0% | 10.1× → **8.4×** |
| ④ multi + demo제외 | 88.9% | 30.2% | 12.0% → 3.7% | 7.4× → **8.2×** |

절대 수치는 52pp 떨어졌지만 배수는 거의 그대로입니다(④는 오히려 0.8 상승).
**하락분의 대부분이 후보 풀 확대(13→33)와 정답셋 편향 제거로 설명됩니다.**

9쌍은 "노트 작성자가 대응 코드를 바로 찾을 수 있었던 chunk"만 모인 집합이었습니다.
43쌍은 "논문 단락 아무거나"에 가깝습니다.

### 2.3 43쌍 최종 수치 (④ multi + 대상 저장소 33블록)

| 지표 | 값 | 랜덤 대비 |
|---|---|---|
| Top-1 | 30.2% (13/43) | 3.7% 대비 **8.2배** |
| Top-3 | 53.5% (23/43) | 11.0% 대비 **4.9배** |
| **Top-5** | **69.8% (30/43)** | 18.3% 대비 **3.8배** |
| MRR | 0.4703 | — |

**Top-5 가 제품과 맞는 지표입니다** — `/api/mapping/search` 가 화면에 5개를 보여줍니다.
지표에 Top-5 가 없어서 이번에 추가했습니다(`c0dc512`).

### 2.4 보고서 대표 수치 (합의)

- **43쌍 단독 사용**, 9쌍은 "예비 측정"으로 각주 처리
- 절대 수치 옆에 **랜덤 하한 대비 배수 병기** — `25.6%` 만 쓰면 나쁘게 읽히지만
  `25.6% (랜덤 3.0% 대비 8.4배)` 는 정직하면서 방어됩니다
- Top-3 배수(4.9배)도 함께 적어 배수를 부풀리지 않았음을 드러냄

## 3. 하이브리드 검색 — 이득 확인, 다만 조건부

9쌍에서는 이득이 없어 보여 우선순위를 내리기로 했으나, 43쌍에서 뒤집혔습니다.

| scorer | Top-1 | Top-3 | MRR |
|---|---|---|---|
| lexical jaccard | 18.6% | 58.1% | 0.3984 |
| vector | 30.2% | 53.5% | 0.4703 |
| **hybrid α=0.7 + jaccard** | **34.9%** | 60.5% | **0.5062** |

어휘는 1위를 잘 못 맞히지만 **Top-3에서는 벡터를 이깁니다**(58.1% vs 53.5%).
두 신호가 서로 다른 것을 잡고 있어 융합이 작동합니다. 9쌍에서는 8/9가 이미 천장이라 안 보였습니다.

### 3.1 ⚠️ jaccard 와 dice 는 하이브리드에서 다릅니다

순수 어휘 랭킹에서는 세 데이터셋 연속 동률이라 "아무거나"로 보였지만,
`dice = 2J/(1+J)` 는 **단조변환이라 순위만 같고 점수 값이 다릅니다.**
가중합에 넣으면 실효 어휘 가중치가 달라집니다.

| α | jaccard | dice |
|---|---|---|
| 0.7 | **34.9% / 0.5062** | 32.6% / 0.4966 |
| 0.9 | — | **34.9% / 0.5087** |

**`dice` 로 확정하면서 α=0.7 을 그대로 쓰면 34.9% 가 아니라 32.6% 가 나옵니다.**
dice 로 가려면 α 를 0.9 부근으로 재조정해야 합니다.

### 3.2 기록 문구

> 43쌍 기준 hybrid(α=0.7, **jaccard**)가 vector 단독 대비 Top-1 +4.7pp / MRR +0.036.
> 단 α 는 동일 정답셋에서 선택했으므로 낙관 편향 가능하며, 효과 크기는 2~3쌍 수준.
> 적용 시 재검증 필요. 적용 시점은 `seed_dump.sql` 이후. RRF 미측정.

## 4. `__init__` 흡인체 — 가설 반증

A가 발견한 새 패턴입니다. 생성자끼리 서로 구분이 안 됩니다.

| | 값 |
|---|---|
| 33블록 중 `__init__` | **10개 (30%)** |
| `__init__` 가 1위를 차지 | 20/43 (46.5%) |
| 정답이 `__init__` 일 때 Top-1 | 25.0% (4/16) |
| 정답이 그 외일 때 Top-1 | 33.3% (9/27) |

`508`·`515` 흡인체의 후속판이되 원인이 다릅니다 — 입도가 아니라 **동종 심볼 간 어휘 공유**입니다
(`d_model`, `n_head`, `dropout`, `nn.Linear`, `super().__init__`).

### 4.1 "어휘 스코어러가 이를 푼다"는 가설은 틀렸습니다

| | `__init__` 1위 | 그중 오답 | 정답=`__init__` Top-1 | 그 외 |
|---|---|---|---|---|
| lexical jaccard | **23/43** | 20 | **12.5%** | 22.2% |
| vector | 20/43 | 17 | 25.0% | 33.3% |
| hybrid α=0.7 | **20/43** | 16 | 31.2% | 37.0% |

- **어휘 단독이 생성자에 더 취약합니다** — `__init__` 1위 비율이 오히려 높고(23/43),
  정답 적중은 절반(12.5%)입니다. Jaccard 는 합집합으로 정규화하므로
  `EncoderLayer` 토큰 하나가 **더** 희석됩니다
- 하이브리드를 써도 `__init__` 1위 비율은 **20/43 으로 변화 없음**
- 하이브리드 이득(+1쌍씩)은 두 그룹에 고르게 퍼져 있고 생성자에 집중되지 않음

**→ 하이브리드는 `__init__` 문제를 풀지 않습니다.** 조치 후보에서 제외.
남은 후보는 ① 임베딩 텍스트에 심볼 경로 가중, ② 생성자를 클래스 docstring 과 묶어 인덱싱.
하이브리드가 **왜** 먹히는지는 아직 미해명입니다.

## 10. 기록해둘 판단 근거

- **9쌍 수치는 보고서에 대표로 쓰지 않습니다.** 노트 작성자가 대응 코드를 바로 찾을 수 있었던

- **jaccard/dice 는 순수 어휘에서만 동등합니다.** 하이브리드에서는 다릅니다(§3.1).
- **하이브리드는 `__init__` 문제를 풀지 않습니다.** 측정으로 확인했습니다(§4.1).
- **α 는 평가에 쓴 정답셋에서 골랐습니다.** 적용 시 재검증이 필요합니다.
