## 2. A — 저장소 소싱 실증 (#38)과 데이터 검수 마감 (#39)

### 2.1 후보추천 스크립트 — "방법이 돈다"의 증명

카탈로그 7편에 정답을 아는 상태로 돌려 재현시켰습니다: **4편은 1위 정확히 일치,
6편은 상위 3위 안** (승인 흐름 §1.3 기준 6/7 성립). Attention 은 우리 선택(재구현)보다
나은 답(저자 공식 구현 `tensor2tensor`)을 1위로 냈습니다.

부딪혀서 확정된 판단 4가지가 전부 기록됐습니다:

- **HF datasets-server 가 작업 중 죽음** → 색인(`database/pwc/links.tsv.gz`, 링크
  283,772건)을 커밋해 기본 경로로 — 외부 서비스 생존에 의존하면 제10조① 위반
- 쿼터는 사전 선별(싼 신호로 자르고 상위 25곳만 API)로
- **라이선스는 3상태** — NOASSERTION 을 '없음'으로 취급하면 darknet(우리 카탈로그
  저장소)이 조용히 사라짐. CONTRIBUTING §7 규칙을 자기 스크립트가 어긴 것을 잡음
- **강한 신호가 라이선스로 빠지면 반드시 알림** — DDPM 공식 구현(star 5,298)이
  LICENSE 없음으로 제외될 때 사유를 출력

B 검증: 커밋된 색인으로 BERT 직접 재현(1위 `google-research/bert`), CC-BY-SA-4.0
파생물 고지(제8조⑤) 확인 후 머지.

### 2.2 `_unresolved` 재동기화 — 제출물의 판단 기록 검수

ingest JSON 의 미해결 기록 273건 중 179건이 이미 해결된 항목이었습니다(여러 라운드의
수정이 기록에 반영 안 됨). 심사자가 열면 해결된 것까지 미해결로 읽는 문제. 94건으로
정리, 영문 초기 기록 17건 우리말 통일. **"demo 논문 최종 검수"(3주차 A 항목)는 이걸로
완료 처리.** 부수 실측: 원문 일치율은 99.2%가 아니라 **99.5%(374/376)** — 나머지
2건은 큐레이터 작성 요약 단락이라 누락이 아님.

## 3. B — 계획 변경: 단락 분리기를 지금 구현 (#41 → #42)

### 3.1 왜 계획을 바꿨나

§5.1 을 Future Work 서술로 두려던 것을 **구현 + 실측**으로 승격(사용자 결정, 8.16).
수동 큐레이션 9편이 곧 정답셋이라 **자동 분리를 사람 판단과 직접 채점할 수 있는**
드문 조건을 활용했습니다. 지킨 것: 카탈로그 DB·seed_dump·데모 불변(독립 실험 경로),
타임박스 8.18 — 실제로는 당일 완료.

### 3.3 교정 과정이 §5.1 설계의 재확인이었다

프롬프트 v1 은 "실험 결과·학습 설정은 보통 비매핑" 같은 **범주 휴리스틱**을 줬고
거짓 억제가 **30%** 였습니다 — "warmup 4000 steps" 단락을, 구현 심볼
`_get_lr_scale` 이 목록에 있는데도 눌렀습니다. **심볼 대조를 유일한 기준으로**
바꾸고 "설정 값도 구현"을 명시하자(v3) **7%** 로 내려왔습니다. A 가 #34 리뷰에서
지적한 "판단 근거는 논문이 아니라 저장소에 있다"가 프롬프트 수준에서 재확인된 것.

구현 중 확정된 설계 판단:

- **cut 목록 계약** — "문단 파티션을 나열하라"는 제약은 LLM 이 자주 어긴다(첫 실행
  55개 중 33개 폴백). "자를 위치만 내라"로 바꾸면 어떤 부분집합도 유효해서 실패
  모드 자체가 사라진다
- **\subsection 선분할** — 문서 구조가 이미 주는 경계는 LLM 에게 묻지 않는다
- **mappable=false 는 억제가 아니라 배지로만** — 거짓 억제 7% ≠ 0. 오류 비용
  비대칭 원칙의 실전 적용
- 남은 거짓 억제에 References→LayerNorm 매핑(큐레이터 특유 판단) 포함 — 자동화가
  따라가지 못하는 것이 정직한 한계

## 7. 기록해둘 판단 근거

- **정답을 아는 데이터로 자동화를 채점한다.** 후보추천(#38)은 "우리 선택을 다시
  찾는가"로, 단락 분리(#42)는 "수동 chunk 와 정렬되는가"로 검증했다. 수동 큐레이션의
  가치가 "데이터"에서 "채점 기준"으로 한 번 더 쓰였다.
- **LLM 프롬프트의 범주 휴리스틱은 개별 근거를 누른다.** "학습 설정은 보통 비매핑"
  이 심볼 목록보다 세게 작용해 거짓 억제 30%를 만들었다. 판단 기준을 하나(심볼
  대조)로 좁히는 편이 정확했다.
- **LLM 에게 지키기 어려운 출력 제약을 걸지 말고, 어떤 출력이든 유효한 계약으로
  바꾼다.** 파티션 나열(자주 위반) → cut 목록(위반 불가능).
- **지표는 컷·조건과 함께 적는다.** MRR 사례 — 값이 맞아도 조건이 빠지면 "유리한
  걸 골랐다"는 인상에 방어가 안 된다.
- **문서끼리 다른 말을 하게 두지 않는다.** 기획서 §5 와 확장기능 §1.5 — 심사자는
  어느 쪽을 읽을지 모른다.
- **안정화된 것을 다시 여는 비용을 확장 이득과 비교한다.** 12→15 보류의 근거.
