## 어떻게 풀었나 — 코드 역매칭

노트에 파일 경로·심볼명이 없어도 **코드 본문이 있으면 위치를 찾을 수 있습니다.**
저장소 원문을 전부 받아 놓고 노트 코드를 역으로 찾는 방식입니다.

1. **줄 단위 매칭** — 노트 코드의 각 줄을 저장소 전체 역인덱스에서 조회, 최다 득표 심볼 채택
2. **공백 무시 매칭** — 노트 코드가 재포맷(줄바꿈 변경)된 경우를 위해 공백을 전부 제거한
   본문에서 32자 창을 16자 간격으로 훑고, **저장소 안에서 유일한 조각만** 득표로 인정
3. 찾은 위치에서 언어별 심볼 파서로 경계를 확정
   - Python → `ast`
   - C → 중괄호 매칭 (darknet)
   - Caffe `.prototxt` → `layer { }` 블록 (ResNet)
   - darknet `.cfg` → `[section]` 블록 (YOLO)

찾은 뒤에는 §4 입도 규칙(부모–자식 동시 인덱싱 금지)을 적용하고,
`codeContent`는 노트 것이 아니라 **저장소 원문에서 잘라** 넣습니다.

## 문제 1. ResNet · U-Net · YOLO에 코드 블록이 하나도 없음 (높음)

**205개 chunk가 들어갔는데 대응 코드가 0건입니다.** 세 논문 전체가 여기 해당합니다.

이 세 노트는 `### 대응 코드` 아래에 코드 본문만 있고 **파일 경로와 심볼명이 없습니다.**

```markdown
### 대응 코드

공식 저장소에서 깊은 모델은 각각 별도의 Caffe 네트워크 정의로 제공됩니다.

```
name: "ResNet-50"
input: "data"
...
```
```

`code_blocks.file_path`는 NOT NULL이라 경로 없이는 행을 만들 수 없습니다.
경로를 추정해서 넣는 것은 검수 리포트 §6에서 겪은 문제(저장소와 불일치하는 코드가
DB에 들어가는 것)를 그대로 반복하므로 비워 뒀습니다.

저장소 자체는 특정했고 `repositories`에는 정상 등록돼 있습니다.

| 논문 | 저장소 | 추가 제약 |
|---|---|---|
| ResNet | `KaimingHe/deep-residual-networks` | Caffe `.prototxt` 배포 파일만 있고 학습 코드가 없음 |
| U-Net | `Miltos-90/UNet_Biomedical_Image_Segmentation` | 비공식 재구현 (★33) |
| YOLO | `pjreddie/darknet` | C 코드 — 현재 AST 파이프라인이 Python 전용 |

### 해결법

**1순위 — 노트에 파일 경로·심볼명 추가.** 다른 6편처럼 `### 대응 코드` 앞에
경로와 심볼을 적어주면 그대로 재변환됩니다. 형식은 아래 §5의 표준 서식을 쓰면 됩니다.

**ResNet은 저장소 선택부터 다시 봐야 합니다.** 공식 저장소에 학습 코드가 없어서
노트도 대부분을 `(예상코드)`로 표시해 뒀습니다. 두 가지 선택지가 있습니다.

- `.prototxt`를 그대로 블록으로 넣기 — `programming_language='Prototxt'`,
  심볼은 `name: "ResNet-50"` 같은 네트워크 정의 단위. AST 대신 라인 파싱이 필요
- 재구현 저장소를 `relation_type='COMMUNITY'`로 추가 (예: `pytorch/vision`의
  `torchvision/models/resnet.py`) — seed_demo가 이미 이 저장소를 쓰고 있음

**YOLO는 C 파서가 필요합니다.** darknet의 `src/*.c`에서 함수 경계를 잡으려면
정규식 기반 파서(중괄호 매칭)를 따로 만들어야 합니다. 우선순위는 낮게 보고,
급하면 `cfg/yolov1.cfg` 같은 설정 파일을 블록 단위로 넣는 쪽이 빠릅니다
(노트에 `yolov1.cfg`가 7회 언급돼 있음).

### ✅ 해결 — 코드 역매칭으로 노트 수정 없이 처리

노트에 경로가 없어도 **코드 본문이 어느 파일 어느 줄에서 왔는지는 저장소를 뒤지면 알 수 있습니다.**
세 저장소의 원문을 전부 받아(ResNet 3개 · U-Net 5개 · darknet 173개 파일)
노트 코드를 역매칭했습니다.

| 논문 | 블록 | 매핑 | 파서 | 저장소 선택 |
|---|---:|---:|---|---|
| ResNet | 14 | 21 | `.prototxt` `layer { }` 블록 파서 | 공식 저장소 유지 |
| U-Net | 15 | 30 | Python AST | 재구현 저장소 `COMMUNITY` |
| YOLO | 7 | 13 | C 중괄호 매칭 + `.cfg` `[section]` 파서 | 공식 저장소 유지 |

- **ResNet**: 저장소 재선정 없이 `.prototxt`를 그대로 블록으로 넣었습니다.
  심볼은 `name: "..."` 단위(`res2a_branch2a` 등), `programming_language='Prototxt'`
- **YOLO**: C 파서를 실제로 만들었습니다. 다만 노트가 인용한 코드 대부분이
  `.cfg` 설정이라 확정된 블록 7개 중 6개가 `Config`, 1개가 `C`입니다
- **U-Net**: 재구현 저장소라 `relation_type='COMMUNITY'`로 등록 (공식 구현이 없는 논문)

## 문제 2. ViT 매칭률이 9% (33 chunk 중 3블록) (높음)

경로는 28건이 잡혔는데 심볼 특정이 20건 실패했습니다.

원인은 `vit_jax/models_vit.py`가 **Flax(JAX) 구조**라는 것입니다. PyTorch처럼
`class X(nn.Module)` + `def forward`가 아니라 `nn.Module` 서브클래스에
`__call__`이 붙는 형태라, 노트가 인용한 코드 조각이 심볼 경계와 잘 안 맞습니다.
게다가 노트 코드가 설정 스니펫(`hidden_size=768` 등) 위주여서 본문 매칭도 실패합니다.

### 해결법

- 노트에서 심볼명을 `Encoder1DBlock`, `MlpBlock`, `VisionTransformer` 처럼
  **클래스명으로 명시**하면 바로 붙습니다 (현재 파서가 클래스도 처리함)
- `flax/linen/attention.py`는 `google/flax` 저장소 소속이라 제외했습니다.
  ViT 노트가 이 파일을 참조한다면 `google/flax`를 `relation_type='REFERENCE'`로
  별도 등록해야 합니다

### ✅ 해결 — 참조 구현 추가 + 주제별 수동 매핑 (4 → 16블록, 5 → 28 chunk)

역매칭만으로는 4블록에 그쳤습니다. ViT 노트가 인용한 코드가
`x = x.reshape(x.shape[0], -1, x.shape[-1])` 같은 **한두 줄짜리 일반적인 텐서 연산**이라
저장소 안에서 유일한 조각이 못 되고, 억지로 통과시키면 엉뚱한 심볼에 붙기 때문입니다.

근본 원인은 **공식 저장소가 Flax 압축 구현**이라는 것입니다. `VisionTransformer.__call__`
하나에 patch embedding·cls token·position embedding이 전부 들어 있어서, 노트의 세분화된
chunk(QKV 생성 / Softmax / Output Projection …)에 대응할 심볼 자체가 없습니다.

그래서 `lucidrains/vit-pytorch`(★25.5k)를 `COMMUNITY`로 추가하고 주제별로 매핑했습니다.
이 구현은 `Attention.__init__`(to_qkv) / `Attention.forward`(softmax) / `FeedForward.__init__`(GELU)
처럼 논문 서술 단위와 심볼이 1:1로 맞습니다.

학습·체크포인트 계열 chunk(데이터 파이프라인·optimizer·LR schedule·체크포인트 로딩)는
**공식 저장소에 실제로 있으므로** `vit_jax/input_pipeline.py`·`train.py`·`checkpoint.py`에 붙였습니다.

남은 5건은 Fine-tuning Strategy·Hybrid Architecture 등 두 저장소 모두에 대응 코드가 없는 항목입니다.

## 문제 3. chunk 53개의 content가 논문 원문이 아님 (높음)

노트에 논문 인용문이 없어서 **구현 설명(한국어)을 content로 넣었습니다.**
검수 리포트 §5에서 "content는 논문 원문 문단"으로 정한 기준에 어긋납니다.

분포는 ResNet 19 · U-Net 7 · YOLO 6 · CLIP 10 · BERT 5 · ViT 3 · Llama 3입니다.

§5 측정에서 확인했듯 chunk 텍스트는 검색 품질에 가장 크게 작용하는 변수라,
이 53건은 검색 결과를 직접 떨어뜨립니다.

### 해결법

- 해당 chunk에 논문 원문 인용을 추가 — `_unresolved`에 chunk 태그가 다 남아 있음
- 원문 인용이 곤란하면 최소한 `subsectionTitle`에 한국어 설명을 옮기고
  content는 비워 두는 편이 낫습니다. 잘못된 텍스트가 임베딩되는 것보다
  chunk가 없는 편이 검색 품질에는 유리합니다

### ✅ 해결 — arXiv 원문에서 문단을 가져와 보강 (373/448)

검수 리포트 §5에서 Attention 논문에 적용한 처리를 9편 전부에 확대했습니다.
ar5iv에서 논문 전문을 받아 두 단계로 붙였습니다.

1. **인용문 매칭 (208건)** — 노트 인용문을 논문 본문에서 찾아 그 문단 전체를 덧붙임
2. **절 단위 보강 (109건)** — 인용문이 없으면 노트의 `논문 위치`(Section 번호)로 해당 절을 찾고,
   **같은 절을 가리키는 chunk들에 그 절의 문단을 순서대로 배분**

2번에서 "첫 문단을 전부에게" 주면 chunk 12개가 같은 텍스트를 갖게 돼(SAM 기준)
임베딩이 구분되지 않습니다. 배분 방식으로 바꿔 최다 중복이 CLIP 11 → 4,
Latent Diffusion 11 → 3, ViT 11 → 6으로 내려갔습니다.

`sectionTitle`도 논문의 실제 절 이름으로 교체했습니다(노트의 한국어 제목은
`subsectionTitle`에 남아 있습니다). §5에서 정한 것과 같은 배치입니다.

**68건은 여전히 미보강입니다** — 인용문도 절 번호도 없는 chunk라 특정할 근거가 없습니다.
노트 설명을 그대로 두고 `_unresolved`에 남겼습니다.

## 문제 4. 노트 서식이 3종류로 갈림 (중간)

파서를 두 개 만들어야 했습니다.

| 서식 | 논문 | 구조 |
|---|---|---|
| A-1 | BERT · CLIP · ViT | `# CHUNK NN` + `## 논문 위치` / `## 논문 원문` / `## 구현 목적` / `# Git 코드` |
| A-2 | Llama · SAM · Stable Diffusion | 같은 구조인데 헤딩에 `①②③` 번호가 붙고 레벨이 `#` |
| B | ResNet · U-Net · YOLO | `# N페이지` + `## N. 제목` + `### 논문 텍스트` / `### 대응 코드` / `### 판정` |

같은 항목의 이름도 갈립니다 — `논문 원문` / `논문 내용` / `논문 핵심 텍스트` / `논문 텍스트`,
`구현 목적` / `논문 구현 의미` / `논문 의미`.

### 해결법 — 표준 서식 고정

다음 노트부터는 아래 형태로 통일하면 파서 하나로 끝납니다.
**`파일`과 `심볼`이 필수**라는 점이 핵심입니다.

```markdown
# CHUNK 01

## 제목
Multi-Head Attention

## 논문 위치
Section 3.2.2
Page 4-5

## 논문 원문
> Multi-head attention allows the model to jointly attend to information
> from different representation subspaces at different positions.

## 구현 목적
h개 head로 나눠 병렬 attention 후 concat.

## Git 코드
파일: transformer/SubLayers.py
심볼: MultiHeadAttention.forward

## 매칭 근거
projection → 병렬 attention → concat → 최종 projection 순서가 논문과 1:1
```

- `심볼`은 `클래스.메서드` 형태로 적으면 동명 심볼 문제(문제 6)도 같이 해결됩니다
- 코드 본문은 **노트에 붙이지 않아도 됩니다.** 어차피 저장소 원문으로 교체하므로
  붙여도 안 쓰입니다 (§6에서 확인된 재포맷 문제)

## 문제 5. 노트가 지목한 경로가 저장소에 없음 (중간, 13건)

| 논문 | 경로 | 실제 소속 |
|---|---|---|
| CLIP | `train.py`, `data.py` | `openai/CLIP`이 아니라 `mlfoundations/open_clip` |
| CLIP | `사용자 코드 영역`, `README Example` | 파일이 아님 |
| ViT | `flax/linen/attention.py` | `google/flax` |
| BERT | `bert_config.json` | 저장소가 아니라 배포 체크포인트에 포함 |
| Latent Diffusion | `scripts/` | 디렉터리 |

SAM·ViT의 일부는 basename 매칭으로 자동 복구했습니다
(`predictor.py` → `segment_anything/predictor.py`).

### 해결법

- 다른 저장소 코드를 참조할 거면 그 저장소를 `paper_repositories`에
  `relation_type='REFERENCE'` 또는 `'COMMUNITY'`로 등록. 스키마가 다대다라 가능합니다
- 파일이 아닌 항목(`사용자 코드 영역` 등)은 노트에서 `Git 코드` 섹션을 아예 비우는 게 맞습니다

### ✅ 해결 — 잘못된 경로를 무시하고 코드 본문으로 재특정

노트의 경로는 이제 **힌트**로만 씁니다. 저장소에 없으면 basename으로 정규화해 보고,
그래도 없으면 경로를 버리고 코드 본문 역매칭으로 저장소 전체를 훑습니다.
그 결과 `train.py`(open_clip) 처럼 잘못 적힌 경로가 있어도 코드가 실제로 있는 곳을 찾습니다.

`사용자 코드 영역` 같은 비파일 항목은 코드 본문 역매칭도 실패하므로 자동으로 제외됩니다.
`google/flax` 참조는 여전히 미등록입니다 — 필요하면 `REFERENCE`로 추가하면 됩니다.

## 문제 6. 동명 심볼 중복 (낮음, 2건)

`ldm/models/diffusion/ddpm.py`에 `p_losses`와 `p_sample_loop`가 각각 2개씩 있습니다
(`DDPM`과 `LatentDiffusion` 양쪽에 정의). 노트에 부모 클래스 표기가 없어서 제외했습니다.

### 해결법

문제 4의 표준 서식대로 `심볼: LatentDiffusion.p_losses`처럼 부모를 함께 적으면 해결됩니다.

### ✅ 해결 — 코드 본문으로 어느 쪽인지 판별

동명 심볼이 여러 개면 **노트 코드를 그 파일 안에서 역매칭해** 어느 클래스의 것인지 가립니다.
`심볼: LatentDiffusion.p_losses`처럼 부모를 적어주면 그것도 그대로 인식합니다(우선 적용).
Latent Diffusion 블록이 12 → 15개로 늘었습니다.
